# project-context

维护一套只给 agent 使用的项目上下文文档体系。仅当用户当前请求显式触发本技能时，加载后才默认立即进入接手或创建流程；只有项目根目录不明确、存在写入风险、发现冲突或需要用户确认取舍时才询问。

## 激活与写入授权

以下规则优先于本技能内其他流程：

- 只有用户在**当前请求**中明确点名 `project-context`、明确要求创建/读取/更新/审计 `.agent-context/`，或由用户手动调用本技能，才视为获得本次操作授权。
- agent 因普通开发任务而自行加载或想起本技能，不构成用户授权；不得因此读取、扫描或修改 `.agent-context/`。
- 授权只对当前请求有效，不自动延续到后续编码、修 bug、重构、测试、提交或其他任务。后续若要再次操作 `.agent-context/`，必须由用户再次显式触发。
- `.agent-context/` 已存在、此前调用过本技能、当前改动具有长期价值、任务已经完成或文档可能过时，都不能作为自动更新理由。
- 未获得当前请求授权时，不得创建、编辑、追加、重建或审计 `.agent-context/`，不得为它修改 `.gitignore`，也不得把“更新项目上下文”作为任务收尾步骤。
- 获得授权后，才按下述模式执行；本次创建或更新的 `.agent-context/README.md` 和 `agent-handoff.md` 必须写入同样的显式触发约束，防止后续 agent 自动维护。

## 核心原则

- `.agent-context/` 是用户手动触发后才维护的文档，不是普通开发任务的自动副作用。
- 只主动创建和维护 `.agent-context/` 内的文档。
- 把项目已有 `README`、需求文档、设计文档、任务文档、注释、配置和 git 历史作为信息来源，不要改写、替代或污染它们。
- 把可核验信息写成事实；把合理推断标注为“推断”；把缺少依据的信息标注为“待确认”。
- 更新旧内容时保留仍有效的历史，合并新事实，标记过时或冲突内容，不要粗暴全量覆盖。
- 面向后续 agent 写作，不要写成面向普通用户的宣传介绍。
- 优先记录能帮助继续工作的内容：目标、边界、入口、依赖、运行方式、历史变化、决策原因、当前状态、风险和下一步。
- 控制文档密度：主文档给总览，细节拆到专题文档；避免把代码全文、日志全文、重复说明塞进上下文文档。

## 专属文档体系

默认在项目根目录维护：

```text
.agent-context/
├── README.md              # 总入口：新 agent 必读
├── current-state.md       # 当前状态、完成度、最近进展
├── project-map.md         # 目录地图、关键入口、模块关系
├── architecture.md        # 架构、数据流、技术栈、运行方式
├── timeline.md            # 历史修改时间线
├── decisions.md           # 决策记录、取舍和原因
├── task-history.md        # 任务批次、需求变化、完成记录
├── user-preferences.md    # 用户偏好、协作习惯、项目约定
├── risks.md               # 已知问题、风险、债务、待核验项
└── agent-handoff.md       # 接手指南、下一步建议、操作清单
```

项目较小也保持这个目录结构；允许某些文件内容很短，但不要把所有内容压成单个根目录文档。

## 项目根目录判定

- 若用户明确指定项目目录，以用户指定目录为准。
- 若当前目录属于 git 仓库，通常使用 git 工作树根目录作为项目根目录。
- 单仓多包或 monorepo 中，若用户意图、包配置、当前路径或任务范围明显指向某个子包，可把该子包作为本次项目根目录，并在文档中说明依据。
- 若处于 git submodule 内，优先把子模块工作树根目录作为项目根目录；只有用户明确要求上层仓库时才使用上层目录。
- 若没有 git 仓库，使用当前工作目录作为项目根目录。
- 若多个候选根目录都合理且会影响写入位置，先向用户确认。
- 所有 `.agent-context/` 路径均相对项目根目录。

## 版本控制默认规则

- 默认把 `.agent-context/` 视为本地 agent 工作记忆，不纳入 git 管理。
- 在 git 仓库中创建或维护 `.agent-context/` 时，检查项目根目录 `.gitignore` 是否已忽略 `.agent-context/`。
- 若 `.agent-context/` 未被忽略，默认最小化创建或更新项目根目录 `.gitignore`，只添加一条：`.agent-context/`。
- 这是本技能默认流程中唯一允许修改 `.agent-context/` 之外文件的例外；不要借此改动 `.gitignore` 的其他内容、排序或注释。
- 若用户明确声明希望把 `.agent-context/` 作为团队共享的 agent 接续文档纳入版本控制，则不要添加忽略规则，并在写入前执行敏感信息审查。
- 若项目不是 git 仓库，不要为了忽略规则创建 `.gitignore`；只在完成汇报中说明未处理版本控制忽略规则。
- 若 `.agent-context/` 已被 git 跟踪，不要自动移除跟踪；在完成汇报中提示用户如需本地化，应自行执行 `git rm --cached -r .agent-context/` 等版本控制操作。

## 运行模式选择

加载本技能后按以下顺序判断模式：

1. **接手模式**：存在 `.agent-context/README.md`，且用户意图是理解、恢复、接手项目，或用户只是直接调用本技能；先读专属文档，再抽样核验代码和项目文档。
2. **创建模式**：不存在 `.agent-context/` 或核心文件缺失；先读取并保留已有部分内容，再扫描项目并补齐完整文档体系。
3. **更新模式**：存在专属文档，用户要求记录本次修改、刷新状态、维护历史；对比旧文档、代码、项目文档和 git 变化后增量更新。
4. **重建模式**：专属文档明显过时、质量差、冲突多，或用户要求重新整理；保留可用历史，重建结构和当前事实。
5. **审计模式**：用户要求检查准确性、过期情况或文档健康度；只输出问题并可按用户确认后修正。

如果用户只是直接调用本技能但没有额外说明：

- 有 `.agent-context/README.md`：执行“接手模式 + 轻量审计”，输出当前理解摘要和待更新建议。
- 没有 `.agent-context/README.md`：执行创建模式，生成专属文档体系。

## 信息收集顺序

按可信度从高到低收集：

1. 用户本轮明确指令和补充要求。
2. `.agent-context/` 现有文档。
3. git 状态、最近提交、分支、变更摘要。
4. 项目已有文档：`README`、需求、设计、部署、任务、接口文档。
5. 配置文件：包管理、构建、测试、框架、环境示例、容器、脚本。
6. 项目内 agent 指令文件和协作约束，例如 `AGENTS.md`、`.cursorrules`、`.github/copilot-instructions.md` 等。
7. 贡献指南、代码规范、任务路线图、里程碑、环境示例文件，例如 `CONTRIBUTING`、`CODE_STYLE`、`ROADMAP`、`.env.example`。
8. 源码入口、路由、核心模块、测试目录、迁移脚本。
9. 文件命名、目录组织、注释、测试和提交习惯所体现的约定。

不要为了“完整”读取所有大型生成物、依赖目录、构建产物、锁文件全文或二进制文件。默认排除：`.git/`、`node_modules/`、`vendor/`、`dist/`、`build/`、`coverage/`、`.venv/`、大型锁文件全文、二进制文件、生成产物、缓存目录和压缩包。优先用文件列表、搜索和关键文件抽样建立地图。

## 创建模式流程

1. 定位项目根目录。
2. 若 `.agent-context/` 已有部分文件，必须先读取并保留：补齐缺失文件，合并有效信息；冲突内容标为“冲突”或“待确认”，禁止覆盖有效历史。
3. 建立项目快照：目录层级、技术栈、入口文件、运行脚本、测试脚本、配置、已有文档、最近 git 历史。
4. 识别项目目标、主要功能、当前完成度和明显未完成区域。
5. 梳理代码结构：模块职责、关键文件、数据流、外部依赖、运行边界。
6. 从项目文档和 git 历史提取历史脉络；没有依据时写“暂无可核验历史”。
7. 创建或补齐 `.agent-context/` 全部核心文件。
8. 若项目是 git 仓库，按“版本控制默认规则”检查并最小化更新 `.gitignore`。
9. 按 `references/project-context-template.md` 的结构写入内容。
10. 在 `risks.md` 记录信息缺口、冲突、待确认事项。
11. 在 `agent-handoff.md` 写出新 agent 下一步如何继续工作。
12. 向用户简短汇报创建结果、主要判断、版本控制处理和待确认项。

## 更新模式流程

1. 读取 `.agent-context/README.md`、`current-state.md`、`timeline.md`、`decisions.md`、`task-history.md`、`risks.md` 和 `agent-handoff.md`；若涉及用户偏好、协作习惯或项目约定变化，同时读取 `user-preferences.md`。
2. 查看当前工作区变化、最近提交、相关代码和项目文档变化。
3. 判断本次更新属于：功能新增、缺陷修复、重构、设计调整、需求变化、分析结论、文档维护或环境变更。
4. 更新 `current-state.md`：当前阶段、完成度、最近进展、阻塞项。
5. 更新 `timeline.md`：追加有日期的变更记录，说明依据。
6. 更新 `task-history.md`：记录任务意图、执行结果、影响范围。
7. 更新 `decisions.md`：只记录有长期影响的选择，不把普通实现细节写成决策。
8. 更新 `project-map.md` 或 `architecture.md`：仅当结构、入口、技术栈、数据流发生变化时修改。
9. 更新 `risks.md`：关闭已解决风险，新增发现的风险和待确认项。
10. 更新 `agent-handoff.md`：刷新下一步建议和接手注意事项。
11. 若项目是 git 仓库，按“版本控制默认规则”检查并最小化更新 `.gitignore`。
12. 只记录用户在当前请求中明确要求纳入上下文的项目变更；不得因为发现变更具有长期价值而扩大授权范围或在后续任务中自动更新。

## 接手模式流程

1. 先读 `.agent-context/README.md` 和 `agent-handoff.md`。
2. 再按需要读取 `current-state.md`、`project-map.md`、`architecture.md`、`risks.md`。
3. 抽样核验关键事实：项目入口、运行脚本、主要目录、最近 git 变化。
4. 输出简短接手摘要：项目目标、当前状态、关键入口、近期重点、风险、下一步。
5. 若发现文档过时或冲突，只列出待更新点；仅当用户在当前请求中明确要求修正时才进入更新模式。

## 重建模式流程

1. 备份或保留旧 `.agent-context/` 的有效信息，不要直接删除历史；可移动到 `.agent-context/archive/`，或在对应文件增加“已过时内容”章节。
2. 标出旧文档中的事实、过时内容、冲突内容和无依据内容。
3. 重新扫描项目文档、配置、代码和 git 历史。
4. 按当前模板重组 `.agent-context/`。
5. 在 `timeline.md` 中记录“上下文文档重建”事件，说明旧内容保留位置和重建依据。
6. 在 `risks.md` 中保留仍待确认的历史断点。

## 审计模式流程

1. 对照 `.agent-context/` 与当前代码、配置、项目文档、git 状态。
2. 按类型列出问题：过时、冲突、缺失、无依据、重复、过细、不可执行。
3. 按严重度分级：严重、中等、轻微、建议优化。
4. 每个问题写明涉及文件、冲突依据、建议修复方式、是否需要用户确认。
5. 未经用户要求，不要在纯审计模式中大规模改写文档。

## 冲突和权限处理

- 如果 `.agent-context/` 已被项目另作他用，或其中内容明显不是本技能文档体系，停止写入并询问用户。
- 如果没有写权限，输出计划和待创建或待修改内容摘要，不要尝试写入项目原有文档目录作为替代。
- 如果项目已有文档与代码、配置或 `.agent-context/` 冲突，保留原文，记录冲突依据和待确认项。
- 不写入项目原有文档目录；即使用户另行要求修改项目原有文档，也应作为独立任务处理；除“版本控制默认规则”中为忽略 `.agent-context/` 而最小化修改项目根目录 `.gitignore` 外，本技能流程只修改 `.agent-context/`。

## 写作标准

- 使用中文。
- 使用标题、列表、表格和短段落。
- 每个文件开头写明：用途、文档体系版本、最后更新日期、最近核验日期、信息来源摘要、可信度和维护说明。
- 对关键事实尽量写明依据，例如“依据 package.json scripts”“依据最近 10 条提交”“依据 src/main.ts”。
- 每条历史记录包含：日期、类型、摘要、影响范围、依据、后续影响。
- 每条决策记录包含：背景、选择、原因、替代方案、影响、状态。
- 每条风险包含：现象、影响、证据、建议、状态、负责人或待确认方。
- 不把“看起来可能”写成事实；用“推断：”或“待确认：”标识。

## 更新边界

- 只有用户当前请求显式触发本技能时，才可以读取或修改 `.agent-context/`；授权不得跨请求延续。
- 可以创建和编辑 `.agent-context/` 内文件。
- 本技能流程内不编辑项目已有文档；若用户另行要求修改项目文档，应作为独立任务处理，并继续保持 `.agent-context/` 为本技能唯一维护区。
- 唯一默认例外：可为忽略 `.agent-context/` 最小化创建或更新项目根目录 `.gitignore`，且只能添加 `.agent-context/` 忽略规则。
- 不要创建本技能之外的 README、CHANGELOG、安装说明等辅助文档。
- 不要把 `.agent-context/` 当成任务管理器替代品；只记录对 agent 接续有长期价值的信息。
- 不要记录秘密、令牌、私钥、密码或敏感凭据；只记录配置位置和安全处理方式。

## 完成前自检

结束前检查：

- 核心文件是否齐全，文件头是否完整。
- 信息来源是否可信，推断是否标注为推断，待确认项是否列出。
- 是否未泄露秘密、令牌、私钥、密码或敏感凭据。
- 是否未误改项目原有文档或原有文档目录。
- 是否确有用户当前请求的显式触发；是否避免把授权延续到后续任务或自动收尾更新。
- git 仓库中 `.agent-context/` 是否已被 `.gitignore` 忽略；如未忽略，是否已按规则只添加 `.agent-context/`。
- 是否保留有效历史，未把冲突或无依据推断写成事实。
- `agent-handoff.md` 是否已更新到足以让下个 agent 接手。
- 用户本次明确要求记录的项目变更，是否已更新到当前状态、时间线、任务历史或接手指南。

## 完成汇报

完成后只向用户汇报：

- 创建或更新了哪些 `.agent-context/` 文件。
- `.agent-context/` 的版本控制处理：已加入 `.gitignore`、已存在忽略规则、用户要求纳入版本控制、非 git 仓库未处理，或已被跟踪需用户自行处理。
- 本次确认的项目状态和主要变化。
- 发现的冲突、风险或待确认项。
- 下次 agent 接手时应先读哪些文件。

不要把完整文档全文贴回对话，除非用户要求。

# `.agent-context/` 文档体系模板

按本模板创建或维护项目专属 agent 上下文文档。保留标题结构；没有信息时写“暂无可核验信息”或“待确认”，不要编造。

## 通用文件头

每个文件开头使用：

```markdown
> 用途：说明本文件帮助 agent 完成什么接续工作。
> 文档体系版本：project-context v1
> 最后更新：YYYY-MM-DD
> 最近核验：YYYY-MM-DD
> 信息来源：列出本次依据的代码、文档、git、用户说明。
> 可信度：高 / 中 / 低；说明主要不确定点。
> 维护说明：仅维护 `.agent-context/` 内上下文；在 git 仓库中，默认将 `.agent-context/` 作为本地 agent 工作记忆并加入 `.gitignore`，非 git 仓库不为此创建 `.gitignore`，除非用户明确要求纳入版本控制；更新时保留有效历史，推断和待确认必须显式标注。
```

## 3.2 文档体系维护规则

- 只更新 `.agent-context/`，不改写项目原有文档。
- 在 git 仓库中，默认把 `.agent-context/` 加入 `.gitignore`，作为本地 agent 工作记忆；非 git 仓库不为此创建 `.gitignore`；若用户明确要求团队共享，则不忽略，但必须先做敏感信息审查。
- 若 `.agent-context/` 已被 git 跟踪，不在本技能内自动移除跟踪，只在交付汇报中提示用户处理。
- 长期有效的项目变化必须同步到当前状态、时间线、任务历史或接手指南。
- 冲突、推断、待确认必须显式标注来源和处理建议。

## 6. 如果要新增需求

1. 读取 `.agent-context/README.md`、`current-state.md`、`project-map.md` 和相关模块。
2. 核对需求是否改变项目目标、架构、接口或运行方式。
3. 实施后把长期影响写入 `task-history.md`，必要时更新 `timeline.md`、`current-state.md`、`project-map.md` 或 `architecture.md`。

## 7. 如果要修 bug

1. 先定位复现路径、相关测试和最近变更。
2. 修复后记录影响范围、验证命令和未覆盖风险。
3. 若暴露长期风险，更新 `risks.md`；若改变行为，更新 `current-state.md` 或 `task-history.md`。

## 8. 如果要重构

1. 先确认重构边界和可回归验证命令。
2. 只把影响入口、模块边界、数据流或长期维护判断的变化写入上下文。
3. 若重构改变架构或目录地图，更新 `architecture.md` 和 `project-map.md`。

## 9. 如果要更新上下文文档

1. 先读取现有 `.agent-context/`，保留有效历史。
2. 对照代码、配置、项目文档和 git 记录更新事实。
3. 推断和冲突不得写成事实；需要确认的内容写入 `risks.md` 或对应文件的待确认段落。

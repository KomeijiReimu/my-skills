# 输出规范

在最终交付前，使用这份清单核对结果。

## 模式规则

- 支持三种模式：只翻译、只解析、同时翻译与解析。
- 用户未明确指定时，默认同时翻译与解析。
- 同时翻译与解析时，建议先完成翻译再做解析。

## 翻译输出

只有当原论文是英文且本轮包含翻译任务时，才创建 `论文stem.translation.zh.md`。

把翻译文件视为可直接交付给第三方读者的正式文本。

译文必须由模型直接写出。不要使用任何脚本、CLI、自动化批处理或外部翻译服务来生成译文。

格式要求：

- 按原文章节和段落顺序翻译。
- 每个译文句子单独成行。
- 段落之间空一行。
- 保留原文的章节编号和小节编号，不要漏掉任何一个已出现的节、小节或子小节。

句子级要求：

- 按原文句子顺序逐句翻译。
- 不要把一个段落压缩成几条总结。
- 原文中的限定条件、转折、举例、数值、比较、结论和解释都要逐句保留。
- 若为了中文通顺而调整句式，也必须保持信息点完整对应。

保真要求：

- 不要对原文做任何转述、总结、改写、润色、美化、提炼、讲解或解释性重写。
- 不要把"原文翻译"写成"论文讲解"。
- 不要把"作者发现……这说明……"写进原本只是陈述性原文的段落中。
- 文风清理不得润色译文或删改原论文真实的否定、术语、比较与限定；只清除 agent 自行添加的包装或解释。

参考文献要求：

- `References`、`Bibliography` 等参考文献部分的条目内容不用翻译。
- 保留原始参考文献条目，不要改写其内容。

在文件开头附近注明：

- 源文件路径
- 论文标题（如果能够可靠识别）
- `模式：翻译`
- "本文件为完整中文翻译"的简短说明

保留所有重要结构：

- 章节和小节标题
- 有序与无序列表
- 图题和表题
- 算法块或编号步骤
- 附录标题
- 存在时的脚注

不要：

- 用总结代替翻译
- 把多句原文压缩成一句概括
- 把段落改写成提炼后的要点列表
- 把一整段先理解后再用自己的话重述
- 把"原文翻译"写成"论文讲解"
- 使用脚本、CLI、批处理程序或外部翻译服务生成译文
- 翻译参考文献条目
- 跳过公式或图表标题
- 把公式写成 Markdown 数学渲染不能解析的形式。公式必须是 LaTeX，行内用 `$...$`，块级用 `$$...$$`，前后定界符各占一行、公式独立成段。不要裸写 `\frac` 一类命令，不要只用 `\(...\)` 或 `\[...\]`，也不要用文字或 Unicode 代替公式
- 不说明就删除附录内容
- 默默掩盖抽取错误或版面缺失

交付前运行本 skill 自带的校验脚本。脚本路径是「本 skill 根目录」（包含 `SKILL.md` 的目录）下的 `scripts/validate_translation_output.py`。不要写死 `~/.config/opencode/...` 或其他本机绝对路径，也不要假设当前工作目录就是 skill 目录：

```bash
python3 "<skill 根目录>/scripts/validate_translation_output.py" "论文stem.translation.zh.md"
```

如果脚本报错，先对照原文核验并修正当前翻译文件的真实问题，再继续下一篇论文。原文真实表达造成误报时保留忠实译文并如实说明，不为通过检查而润色、删句或改术语，也不把误报记为校验通过。

## 解析输出

只有当本轮包含解析任务时，才创建 `论文stem.analysis.zh.md`。

至少覆盖这些内容：

- 文献信息
- 研究问题与动机
- 假设条件与问题形式化
- 记号与定义
- 模型或方法流程
- 目标函数、损失项与优化细节
- 训练设置与实现线索
- 数据集与预处理
- 基线方法与评测协议
- 主要结果
- 消融实验与敏感性分析
- 重要图表和附录发现
- 优势、局限、风险与开放问题

新增解析和说明用普通、可理解的词写清对象、动作和事实，不杜撰“证据门禁”“基线闭环”等 agent 黑话；真实项目及学术术语保留并按需要解释。按语义清除新增文字中的无源否定、虚构预设、无关免责和写作过程泄漏，保留真实限制和必要学术边界；不把这些规则反用于润色原文译文。

## 两类输出的公式与读回检查

- 翻译和解析均遵守上述 Markdown 数学定界符规则，保留数学含义、符号和必要编号；复杂公式也不得用代码块或反引号冒充渲染。原文代码片段或逐字引用里的公式源码按原样保留并标明用途，其外的数学说明仍须渲染；无公式内容不强加公式。
- 交付前按文件规模读回成稿：核对公式格式、译文保真及新增解析/说明的文风。发现问题须实际改回文件并读回复查，无未处理问题才可交付；进度和最终消息同样检查新增表述，不展示内部自检过程，不追加外部流程或其他 skill 依赖。

## 多篇论文处理

如果用户一次给出多篇论文：

- 每篇论文分别生成当前模式对应的输出文件
- 维护完成清单
- 核对每个源文件是否都产生了预期输出
- 即使论文数量很多，也要持续处理到整批任务完成，不能处理中途自行结束

只有当每篇论文都已明确交代结果后，才能报告完成。
